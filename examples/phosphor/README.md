# Phosphor — example theme

A dark, phosphor-green rice evoking the classic "digital plane" look (Matrix / Tron
data-stream aesthetic), built in the visual language of this developer's other tools.
Not an adaptation of any specific community dotfiles repo — an original theme, built for
this task, using the same schemas proven correct in `examples/catppuccin`.

## Design reference

Before picking colors, this theme's palette and typography choices were checked against
`ottosite` (`F:/Projetos/Ativos/ottosite/src/styles/global.css`), which this developer's
own memory notes describe as the canonical visual/brand reference for their tools. That
file's actual design tokens: near-black backgrounds (`#060003`/`#090004`/`#0D0006`), a
single saturated accent color used sparingly with a glow/shadow on hover and headings,
`'JetBrains Mono'` monospace everywhere, a tight `4px` border-radius, uppercase
letter-spaced eyebrow labels, and CRT-adjacent texture (a scanline overlay). Phosphor
reuses that same structural language — near-black bases, one dominant saturated accent
with a soft glow, monospace-first typography, `4px` radii on widgets/badges — recolored
into a green, Matrix-evoking family instead of ottosite's own red/gold.

## Palette

Own identity built around pure "phosphor" greens, not Catppuccin's green and not a flat
neon wash — desaturated/darker variants carry body text and structure so the whole UI
doesn't read as a wall of pure `#00ff41`:

| Role | Hex | Notes |
|---|---|---|
| `bg-deep` | `#010402` | near-black base, GlazeWM desktop / bar backdrop |
| `bg-primary` | `#030906` | bar background (`--bar-dark-bg`, 85% alpha) |
| `bg-secondary` | `#05100a` | popup/menu backgrounds |
| `border` | `#0f3322` | dim moss-green — unfocused window borders, dividers |
| `border-bright` | `#1a5c3a` | brighter border/divider variant |
| `text-primary` | `#baffcb` | soft phosphor — main bar/text color, readable, not pure neon |
| `text-secondary` | `#5fae7c` | muted green — secondary labels, dim state |
| `text-tertiary` | `#35624a` | dimmest — disabled/tertiary text |
| `accent` (primary) | `#00ff41` | pure phosphor green — focused window border, active workspace, cursor color |
| `accent-secondary` | `#00ffa2` | teal-green — secondary highlight (graphs, weather icon, sunrise/sunset) |

Windows Terminal scheme (`configs/wt-scheme.json`) extends this into a full 16-color ANSI
palette: red/yellow/blue/purple/cyan are present (for normal terminal legibility — real
tools print errors in red, warnings in yellow) but desaturated/rotated toward the green
family rather than generic defaults, so the terminal still reads as part of the same
theme instead of clashing with it.

## The wallpaper — Tron-style perspective grid

`assets/wallpaper.png` (3840x2160) and `assets/preview.png` (1040x585) are **not** a flat
gradient like the other example themes' wallpapers — they're generated by a custom script
(not the bundled `gen_gradient.py`, which only does simple gradients), spirited the same
way: near-black-to-dark-green vertical gradient background, plus a perspective floor grid
(horizontal + converging vertical lines toward a centered vanishing point on the horizon,
classic Tron/Matrix "digital plane"), with a faked bloom/glow — PIL has no true bloom
filter, so the glow is built by compositing a heavily-blurred wide copy of the grid, then
a medium-blurred copy, then the sharp grid on top, plus a soft vignette darkening the
edges so the grid reads as emissive against a receding dark plane. Regenerate with:

```
python gen_grid.py --bg-top "#020705" --bg-bottom "#01120a" --line "#00ff41" \
  --wallpaper assets/wallpaper.png --preview assets/preview.png \
  --wallpaper-size 3840x2160 --preview-size 1040x585
```

(script lives alongside this README's source session, not checked into the theme
directory — it's a generator, not theme content). Viewed both outputs directly after
generation: the grid lines genuinely converge to a single point on the horizon (not a
flat repeating pattern), the vanishing point glows brighter than the rest of the grid,
line brightness/width increases toward the viewer (nearer lines = thicker/brighter, a
real perspective cue), and the sky above the horizon stays clean near-black so the floor
reads as the clear focal element — no muddy colors, no washed-out neon.

## Scope — what's covered and why

Minimum viable "reads as a rice" set per this skill's own default guidance:
`glazewm` + `yasb` + `windows_terminal` + `wallpaper`.

**Deliberately left out of scope for this pass** (matching the skill's own guidance not
to over-scope by default — it asks before adding these, and there was no live user to
ask in this session, so the minimal set was kept): `vscode`, `zed`, `fastfetch`,
`flow_launcher`, `oh_my_posh`. Any of these could be added later following the same
palette (`accent` `#00ff41`, `accent-secondary` `#00ffa2`, backgrounds/text above) without
changing the theme's identity. No Windhawk mods either, also per the skill's default (they
require a manual Windhawk 2.0+ alpha install the user has to do themselves first).

PowerShell `$PROFILE` is out of scope by design, same as every other OttoRice theme — it's
a script, and the manifest format never carries scripts (see `examples/catppuccin/README.md`
for the full rationale, unchanged here).

## YASB visual notes

- `bars.status-bar.window_flags.windows_app_bar: true` is set — without it GlazeWM would
  tile/stretch the YASB bar like a normal window instead of reserving its own screen strip.
- Widget CSS classes: every `yasb.*` widget gets a `-widget` suffix on its real class
  (`clock-widget`, `taskbar-widget`, `power-menu-widget`, `open-meteo-widget`); the
  `glazewm.workspaces.GlazewmWorkspacesWidget` widget does **not** — its class is
  `glazewm-workspaces`, no suffix. Verified by grep against both `config.yaml` (every
  `type: 'yasb.*'` widget) and `styles.css` (checked each has a matching `-widget`
  selector, and confirmed no incorrect `-widget` suffix was added to
  `.glazewm-workspaces`). `cpu-widget`/`memory-widget`/`volume-widget` have no bare
  class selector of their own in `styles.css` — same as `examples/catppuccin`, they
  render through the generic `.widget .icon`/`.widget .label` rules, only their popups
  (`.cpu-popup`, `.memory-popup`) get custom styling.
- Only Segoe UI / Segoe Fluent Icons glyphs are used — both ship with Windows 11, no Nerd
  Font install required for any widget in this theme.
- Weather uses `yasb.open_meteo.OpenMeteoWidget`, which needs no API key (not the older
  `weather` widget, which does).

## Verification — what was and wasn't done

**Done:**
- Every JSON file (`rice-manifest.json`, `configs/wt-scheme.json`) parsed with
  `json.load` — valid.
- Every YAML file (`configs/glazewm/config.yaml`, `configs/yasb/config.yaml`) parsed with
  `yaml.safe_load` — valid.
- Every `target.app`/`target.action` pair in `rice-manifest.json` (`glazewm`/`override`,
  `yasb`/`override`, `windows_terminal`/`merge_scheme`, `wallpaper`/`set`) checked against
  the `SupportedApps.cs` whitelist documented in this skill — all four are listed with
  those exact actions.
- Every `source` path in the manifest confirmed to exist on disk relative to the theme
  root (`configs/glazewm/config.yaml`, `configs/yasb`, `configs/wt-scheme.json`,
  `assets/wallpaper.png`).
- `wallpaper.png` and `preview.png` opened and visually inspected after generation — grid
  convergence, glow, and color balance confirmed correct (see wallpaper section above).

**Not done this round:** the YASB config was **not** deployed to
`%USERPROFILE%\.config\yasb\` and **not** reloaded/screenshotted on a live machine — a
concurrent agent may have been actively using the live YASB config on this machine for
its own test at the time this theme was generated, so the live-deploy step was skipped
deliberately to avoid clobbering it. The config is validated for syntax and
whitelist/schema compliance only, matching the honesty convention of the other example
themes' READMEs ("configs validated for manifest format and install pipeline, but not
run against the real apps simultaneously"). If you have a machine with OttoRice + GlazeWM
+ YASB installed, follow the skill's step 6 live-verification checklist (copy
`config.yaml`/`styles.css` to `%USERPROFILE%\.config\yasb\`, `yasbc reload`, screenshot,
check `yasb.log`) before trusting this in daily use.

## How to use

Copy the folder, tweak anything you want, publish to a GitHub repo; in OttoRice paste the
URL (or "ARQUIVO..." pointing at the local `rice-manifest.json` to test before publishing).
